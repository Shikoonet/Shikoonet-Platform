## ۱. چه چیزی از بیرون قابل دیدن است

سه هاست، و همه روی یک ماشین: `164.132.198.184` (Ubuntu 24.04).

| در                          | چه چیزی جواب می‌دهد                                 | جلویش چیست                                                                            |
| --------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `sms.mahamsteel.ir:9443`    | `POST /api/v1/sms` · `GET /health` · `GET /version` | TLS در `shikoo-tls`؛ خودِ ingest: اعتبار دستگاه، حد نرخ per-device و per-IP، سقف بدنه |
| `shikoo.mahamsteel.ir:9443` | SPA پنل + کل `/api/v1/*`                            | همان TLS؛ کوکی نشست اپراتور، `originGuard`، نقش                                       |
| `164.132.198.184:8000`      | پنل Coolify                                         | **فقط رمز خودش، روی HTTP ساده** — بخش ۵                                               |
| `164.132.198.184:22`        | SSH                                                 | فقط کلید (`.notes/deploy_key`)                                                        |

**ربات هیچ در ورودی ندارد.** long polling می‌زند، پس نه پورت، نه گواهی، نه رکورد DNS. این
تصمیم است نه اتفاق: مسیر پول از تلگرام هیچ سطح ورودی به این ماشین اضافه نمی‌کند.

بررسی از بیرون:

```
curl -s -o /dev/null -w '%{http_code}\n' https://sms.mahamsteel.ir:9443/health          # 200
curl -s -o /dev/null -w '%{http_code}\n' https://shikoo.mahamsteel.ir:9443/api/v1/version # 401
```

دومی باید **۴۰۱** باشد. اگر ۲۰۰ شد، گیت نشست از جلوی یک روت افتاده است.

**هیچ فایروالی نیست.** `ufw` نصب نیست و زنجیرهٔ `DOCKER-USER` خالی است — تصمیم صریح Sam برای
دورهٔ تست. یعنی هر پورتی که یک کانتینر publish کند واقعاً عمومی است؛ به همین دلیل هیچ‌کدام از
سه اپ `ports_mappings` ندارند و Postgres هم منتشر نشده:

```
ssh … 'docker port zpuyfk3p3nqfpebybbxz6opy'    # باید خالی باشد
```

## ۲. مرزهای اعتماد

سه مرز، و هرکدام یک نگهبان دارد — نه یک کامنت.

### ۲-۱ · تلفن → ingest

اعتبار دستگاه **در بدنهٔ POST** است، نه در هدر. قرارداد `POST /api/v1/sms` منجمد است چون اپ
اندروید `sms-relay` دست‌نخورده می‌ماند. توکن فقط به‌صورت هش ذخیره می‌شود و ۴۰۱ برای دستگاه
ناشناخته و دستگاه غیرفعال یکی است، تا شمارش دستگاه ممکن نباشد
(`apps/ingest-worker/test/security.test.ts`).

**بدنهٔ خام SMS هرگز لاگ نمی‌شود و OTP هرگز ذخیره، رندر یا لاگ نمی‌شود.**

### ۲-۲ · مرورگر → پنل

از ۲۰۲۶-۰۸-۱۷ که Cloudflare Access از مسیر بیرون رفت، **این چهار روت کل دیوارند**:

|             |                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------- |
| رمز         | scrypt (`N=32768`)، `access_users.password_hash`. متن اصلی هیچ‌جا نیست                   |
| دو مرحله‌ای | TOTP اختیاری، با چک `totp_last_step` تا یک کد دو بار خرج نشود                            |
| قفل         | ۵ تلاش غلط → ۱۵ دقیقه. شمارش **داخل خودِ UPDATE**، نه SELECT-then-UPDATE                 |
| نشست        | کوکی httpOnly، فقط هشِ توکن ذخیره می‌شود؛ ۱۲ ساعت بی‌کاری، ۳۰ روز مطلق                   |
| مبدأ        | `originGuard` روی هر نوشتن. `proxy_set_header Host $http_host` — نه `$host`              |
| حد نرخ ورود | per-IP، **فقط اگر `TRUSTED_PROXY_IP_HEADER` ست باشد** — و پروسه در بوت می‌گوید اگر نباشد |

تغییر رمز از داخل پنل هست (`POST /api/v1/auth/password`) و **رمز فعلی** را می‌خواهد، نه فقط
نشست: نشست یک bearer روی لپ‌تاپی است که ممکن است رها شده باشد.

### ۲-۳ · اپراتور → داده

سه نقش: `ADMIN` · `REVIEWER` · `READ_ONLY`.

- **خواندن:** `mayRead` در `apps/dashboard-worker/src/access.ts` — خطش «عملیات فروشگاه» در
  برابر «چیزی که اسم یک آدم را می‌برد». پیشوندی، تا روتی که فردا زیر `/customers/` اضافه شود
  خودبه‌خود پوشیده باشد.
- **نوشتن:** هر روت گارد خودش را دارد، و از ۲۰۲۶-۰۸-۲۲ این ادعا **سنجیده می‌شود** نه فرض:
  `apps/dashboard-worker/test/write-roles.test.ts` هر ۱۱۴ روت نوشتن را از `app.routes`
  می‌شمارد و از هرکدام می‌پرسد به `READ_ONLY` و `REVIEWER` چه می‌گوید. استثناها در همان فایل
  با دلیلشان نوشته‌اند.

ربات نقش‌های جدا دارد (`admins`: OWNER/ADMIN/SUPPORT با مجوز به ازای هر کار، `may()` در
`packages/contracts/src/adminPermissions.ts`). دو سیستم‌اند برای دو مخاطب و **قاطی نمی‌شوند**.

## ۳. چیزهایی که دیتابیس نگه می‌دارد، نه کد

اگر این‌ها به لایهٔ اپلیکیشن منتقل شوند، مدل تهدید عوض می‌شود:

- **یک تراکنش بانکی نمی‌تواند چند claim را verify کند، و یک claim دو بار settle نمی‌شود** —
  ایندکس partial unique در Postgres.
- `audit_logs` فقط append است؛ تریگر جلوی update و delete را می‌گیرد.
- auto-verify فقط برای جفت ایزولهٔ ۱↔۱: حساب دقیق، مبلغ دقیق بدون تلورانس،
  `|bank_timestamp − paid_clicked_at| ≤ 300000ms`. **هیچ‌وقت auto-reject، هیچ‌وقت رسید ساختگی.**
- اسکیما فقط با مهاجرت نسخه‌دار؛ دروازهٔ بوت روی اسکیمای عقب‌مانده بالا نمی‌آید.

## ۴. چه چیزی هرگز لاگ نمی‌شود

OTP · `apiKey` دستگاه · توکن ربات · کلید HMAC · بدنهٔ خام SMS · رمز اپراتور · توکن نشست.

خطای درایور Postgres **خودِ دستور SQL را همراه دارد** (`packages/db`) — عمدی و مفید، ولی یعنی
هیچ مقدار حساسی نباید به‌صورت literal داخل SQL برود؛ همه‌چیز پارامتر است.

## ۶. آنچه این سند ادعا نمی‌کند

- **بازبینی نفوذ نیست.** هیچ‌کس از بیرون به این سیستم حمله نکرده.
- **دربارهٔ ربات PHP زنده و پنل مشتری حرف نمی‌زند.** هر دو فقط-خواندنی‌اند تا پایان
  پوسته‌اندازی و مدل تهدید خودشان را دارند که ما ننوشته‌ایم.
- **جعبهٔ `164.132.198.184` تمرین است، نه پروداکشن** — تصمیم Sam، ۲۰۲۶-۰۸-۱۹. دیتایش واقعی
  نیست. هر سطر بخش ۵ وقتی معنای دیگری پیدا می‌کند که دادهٔ واقعی مشتری آن‌جا بنشیند، و
  آن روز این سند باید دوباره خوانده شود.
