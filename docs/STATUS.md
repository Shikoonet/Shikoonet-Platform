## راه‌اندازی و اجرا

```bash
pnpm install
pnpm sim:up                                   # Postgres روی 5433، MySQL روی 3307

for f in migrations/000*.sql; do              # اسکیما را بساز
  docker exec -i shikoo-sim-postgres-1 psql -U shikoo -d shikoo -v ON_ERROR_STOP=1 -q < "$f"
done

pnpm typecheck && pnpm lint && pnpm test      # ۸۶۸ تست
```

**تضمین‌های پول** (هر وقت شک کردی، روی هر دیتابیسی امن است — همه‌چیز rollback می‌شود):

```bash
docker exec -i shikoo-sim-postgres-1 psql -U shikoo -d shikoo \
  -v ON_ERROR_STOP=1 -q < migrations/verify_invariants.sql     # باید ۱۹ تا PASS بدهد
```

**مهاجرت دیتای واقعی:**

```bash
pnpm --filter @shikoo/migrate preflight   # فقط می‌خواند — هیچ‌چیز نمی‌نویسد
pnpm --filter @shikoo/migrate migrate     # preflight → مهاجرت → تایید پولی
pnpm --filter @shikoo/migrate verify      # دوباره دو طرف را مقایسه می‌کند
```

**اجرای سرویس‌ها:**

```bash
DATABASE_URL=postgres://shikoo:shikoo_local@127.0.0.1:5433/shikoo \
  pnpm --filter @shikoo/ingest start       # پورت 8787

DATABASE_URL=... TEST_ACCESS_USER=you@example.com \
  pnpm --filter @shikoo/dashboard start    # پورت 8788
```

> `pnpm` روی ویندوز معمولاً روی PATH نیست. یا `corepack pnpm ...` بزن، یا یک شیم بساز:
> `%TEMP%\pnpmshim\pnpm.cmd` با محتوای `corepack pnpm %*` و آن پوشه را به PATH اضافه کن.
> اسکریپت `test` ریشه داخل خودش `pnpm` صدا می‌زند، پس بدون شیم کار نمی‌کند.

## عیب‌یابی — علامت ← علت ← درمان

### تست و دیتابیس

| علامت | علت | درمان |
|---|---|---|
| تست‌ها تصادفی قرمز می‌شوند، `TRUNCATE`/duplicate key | دو پکیج هم‌زمان روی **یک** Postgres تست می‌گیرند و همدیگر را پاک می‌کنند | `pnpm test` ریشه **سریالی** است (`pnpm -r test` بدون `--parallel`). موازی‌اش نکن. |
| `expected 53 tables, found 0` | اسکیما اعمال نشده | حلقهٔ `migrations/000*.sql` بالا را اجرا کن |
| `duplicate key ... devices_pkey` در `verify_invariants` | فیکسچری با دیتای موجود تصادم کرده | نباید بشود — همهٔ فیکسچرها `__inv-` پیشوند دارند. اگر شد یعنی کسی پیشوند را برداشته. |
| `audit_logs is append-only (attempted DELETE)` | کد یا تستی می‌خواهد لاگ ممیزی را پاک کند | این عمدی است. برای ریست در **تست** از `TRUNCATE ... CASCADE` استفاده کن، نه `DELETE`. |
| تست وقتِ‌دار امروز سبز، فردا قرمز | `Date.now()` واقعی خوانده می‌شود ولی انتظار به تاریخ ثابت گره خورده | `vi.spyOn(Date,'now').mockReturnValue(NOW_MS)` در `beforeEach` و `vi.restoreAllMocks()` در `afterEach` |

### آداپتور Postgres (`packages/db`)

| علامت | علت | درمان |
|---|---|---|
| `could not determine data type of parameter $2` | کوئری از قطعات اختیاری ساخته شده و `$2` استفاده نشده | خودکار حل می‌شود (`compactParameters`). اگر باز دیدی، خطا **خودِ دستور را چاپ می‌کند** — از همان‌جا شروع کن. |
| `'4000000' !== 4000000` در مقایسهٔ پول | `SUM(bigint)` در Postgres `numeric` است | آداپتور numeric را عدد می‌کند. اگر عدد بیش از ۱۵ رقم معنادار باشد **خطا می‌دهد**، نه گرد کردن بی‌صدا. |
| مقایسهٔ زمان یا مبلغ همیشه false | ستون `bigint` رشته برگشته | آداپتور `int8` را عدد می‌کند. بیرون از آداپتور کوئری نزن. |
| `column "fa.id" must appear in the GROUP BY` | SQLite ستون غیرتجمیعی را قبول می‌کرد، Postgres نه | کلید اصلی جدول را به `GROUP BY` اضافه کن؛ بقیهٔ ستون‌هایش را Postgres از روی وابستگی تابعی می‌پذیرد |
| `EXISTS(...)` همیشه false | در SQLite عدد ۰/۱، در Postgres بولین | در SQL بنویس `(EXISTS (...))::int` |
| کلید پاسخ `accountid` به‌جای `accountId` | Postgres شناسه‌های بدون کوتیشن را کوچک می‌کند | نام مستعار را کوتیشن بگذار: `AS "accountId"` — یا بهتر، snake_case بنویس |
| `anonymous ? placeholder` یا `mixes ?N and bare ?` | یک دستور هر دو سبک را قاطی کرده | یکدست کن. مترجم عمداً حدس نمی‌زند. |
| `INSERT OR IGNORE ... ON CONFLICT is ambiguous` | هر دو با هم آمده‌اند | یکی را بردار. |

### مهاجرت دیتا

| علامت | علت | درمان |
|---|---|---|
| `unmapped legacy value` | مقدار جدیدی در دیتای قدیمی پیدا شده | **عمدی است** — به `transform.ts` اضافه‌اش کن. هرگز fallback نگذار. |
| پیش‌پرواز «بلاکر» می‌دهد | چیزی هست که مهاجرت را غلط می‌کند | متن بلاکر خودش می‌گوید چه کن. `--force` فقط وقتی که آدمی خوانده و تصمیم گرفته. |
| اختلاف پولی غیرصفر | یک تبدیل خراب است | مهاجرت را قبول نکن. جدولِ ناهم‌خوان در خروجی `verify` مشخص است. |
| `epoch outside the plausible range` | میلی‌ثانیه در ستون ثانیه (یا برعکس) | فرمت واقعی آن ستون را بررسی کن — چهار فرمت مختلف در دیتای قدیمی هست |

## تله‌هایی که یک بار گازمان گرفتند

**۱. `Move-Item` روی پوشهٔ بزرگ نیمه‌کاره تمام می‌شود و خطا هم می‌دهد.** یک بار `.git` کامل این‌طور
رفت و بعد با `Remove-Item -Recurse` پاک شد. از `robocopy <src> <dst> /E` استفاده کن، قبل از حذف
مقصد را بشمار، و cwd هیچ شلی داخل پوشهٔ در حال جابه‌جایی نباشد.

**۲. `GROUP BY` در MySQL به بزرگی حروف حساس نیست.** بررسی اول من مقدار `active` (کوچک) را ندید
چون با `Active` یکی شمرده شده بود. هر بررسی مقدارِ یکتا روی MySQL باید `COLLATE utf8mb4_bin` داشته
باشد — **چک باید دست‌کم به سخت‌گیریِ کدی باشد که چک می‌کند.**

**۳. تستی که فقط با خودش سازگار است هیچ چیز را ثابت نمی‌کند.** باگ ۷ ساعتهٔ «امروز به وقت تهران»
سال‌ها زنده ماند چون تست‌ها فقط بررسی می‌کردند تابع با خودش می‌خواند. حالا با `Asia/Tehran` واقعی
سنجیده می‌شود.

**۴. جداسازی تست‌ها که از پلتفرم می‌آمد، با انتقال ناپدید می‌شود.** Workers به هر فایل تست یک
دیتابیس تازه می‌داد. با یک Postgres مشترک، چهار باگ فیکسچر بیرون زد که سال‌ها پنهان بودند.

**۵. دیتای seed از قبل تضمین پول را نقض می‌کرد** — و کسی نفهمید چون تست‌های seed مهاجرت `0011`
(همان که ایندکس‌های partial unique را می‌سازد) را اعمال نمی‌کردند.

## تصمیم‌هایی که نباید بی‌دلیل عوض شوند

- **تضمین پول در ایندکس است، نه در کد.** `idx_match_one_auto_per_tx` و
  `idx_match_one_auto_per_claim`. یک تراکنش بانکی حداکثر یک claim را تسویه می‌کند. **دلیل اصلی
  انتخاب Postgres همین است** — MySQL ایندکس شرطی ندارد.
- **پول همه‌جا `bigint` ریال.** تومان فقط در لبهٔ ربات وجود دارد.
- **کیف پول دفتر کل است.** هیچ کدی `wallets.balance_irr` را نمی‌نویسد؛ ردیف در `wallet_entries`
  درج می‌شود و تریگر مانده را جابه‌جا می‌کند.
- **`0004_payment_hub.sql` یک پورت مکانیکی است، نه بازطراحی.** اپاک میلی‌ثانیه `bigint` ماند و
  پرچم‌های ۰/۱ `smallint` — چون ۸۰۰ تست و کل `packages/domain` این ستون‌ها را می‌خوانند.
- **مهاجرت هیچ‌وقت پول را دست‌کاری نمی‌کند.** مانده منفی `-5,940,000` تومان عیناً منتقل می‌شود.
  تصحیح‌های آگاهانه فقط در `corrections.ts` با شواهدشان.
- **`legacy/` فقط مرجع است.** کد زنده نیست. در فاز ۵ حذف می‌شود.

### فاز ۴ — ربات جدید

جایگزینی **۶۴٬۷۹۳ خط PHP در ۱۰۴ فایل**. حجیم‌ترین بخش کل پروژه. آنچه تا اینجا ساخته شد زیرساخت
بود؛ ربات هنوز نوشته نشده.

مدل محصول عمومی از قبل در اسکیما هست (`provisioning_providers.kind`), پس افزودن Spotify یا اکانت
هوش مصنوعی یعنی یک آداپتور، نه دست‌زدن به سفارش و کیف پول و تایید پرداخت.

### فاز ۵

بازنشستگی PHP، فیچر به فیچر. حذف `legacy/` و تست `hub-sql.test.ts` که به آن وابسته است.
