# Existing SMS Relay — Outbound Contract

Source: <https://github.com/automagen-ab/sms-relay> (GPL-3.0). Read-only. **Do not** fork, modify, or rebuild the Android app.

See also: `.claude/skills/sms-relay/SKILL.md` for a short reference.

## What the app does

An Android `BroadcastReceiver` (`SmsReceiver.kt`) listens for `Telephony.Sms.Intents.SMS_RECEIVED_ACTION`, concatenates multipart parts, MD5-hashes the body, then enqueues a `WorkManager` job (`SmsWorker.kt`). The worker opens an `HttpURLConnection` to a per-Remote URL with a configurable method and body.

## Per-Remote config (configured manually in the Android app)

Each Remote is a named forwarding rule. Fields the operator sets in the app:

| Field                | Type                   | Default                                                                                | Notes                                                                                     |
| -------------------- | ---------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `name`               | string                 | `"New Remote"`                                                                         | Display only.                                                                             |
| `url`                | string                 | empty                                                                                  | Placeholders substituted.                                                                 |
| `method`             | `GET` \| `POST`        | `POST`                                                                                 | Anything else throws.                                                                     |
| `useFormData`        | bool                   | `true`                                                                                 | Only meaningful for `POST`.                                                               |
| `regexFilter`        | string                 | empty                                                                                  | Matched against `sender`. Non-match → no request, no error.                               |
| `postJsonBody`       | string (JSON template) | `{"message":"{sms_body}","sender":"{sms_sender}","timestamp":"{sms_timestamp}"}`       | Used when `POST` + `!useFormData`. Recursively substitutes placeholders in string values. |
| `formDataParameters` | list of `{key, value}` | `[("message","{sms_body}"),("sender","{sms_sender}"),("timestamp","{sms_timestamp}")]` | Used for `POST` + form-data or `GET` query.                                               |

## Placeholders (substituted by `SmsWorker.replacePlaceholders`)

- `{sms_body}` — full message body (multipart concatenated on-device)
- `{sms_sender}` — originating address (e.g. phone number)
- `{sms_timestamp}` — `SmsMessage.timestampMillis` as a string (epoch ms)
- `{sms_checksum}` — lowercase MD5 hex of the body bytes (computed in `SmsReceiver.kt`)

URL placeholders are URL-encoded; JSON-string placeholders are NOT URL-encoded but are inserted into the JSON tree as-is.

## Headers (set by `SmsWorker`)

- `Content-Type: application/json; charset=utf-8` (JSON) **or** `application/x-www-form-urlencoded; charset=utf-8` (form)
- `Accept: application/json`
- No `Authorization` header. The app does not sign requests.

## Retry / failure

- Retries on non-2xx: up to 3 attempts (`runAttemptCount`), then marked `FAILED` in the app's local log.
- Timeouts: `connectTimeout=15s`, `readTimeout=10s`.

## Transport security

`SmsWorker` installs a permissive `X509TrustManager` that accepts every certificate. **Treat the transport as unauthenticated.** Require an application-layer secret (the `apiKey` field — see below) carried in the body.

## Required static fields for this project

The operator adds three static fields to each phone's Remote JSON body or form-data list, alongside the four dynamic placeholders:

```json
{
  "apiKey": "<STATIC_LONG_RANDOM_SECRET_PER_PHONE>",
  "deviceId": "phone-01",
  "deviceName": "Phone 01",
  "message": "{sms_body}",
  "sender": "{sms_sender}",
  "timestamp": "{sms_timestamp}",
  "checksum": "{sms_checksum}"
}
```

- `apiKey`: ≥32 random bytes encoded as URL-safe base64 or hex. Generated by the ADMIN in the dashboard, displayed once on rotation, **never** stored raw.
- `deviceId`: stable identifier assigned by the ADMIN. The phone is identified by this + its bearer token.
- `deviceName`: human-readable label.

Use `POST` + `useFormData=false` so the body is JSON. The Android app will set `Content-Type: application/json; charset=utf-8`.

## Known device-side limitations

- Cannot set custom headers.
- Cannot sign requests.
- Cannot prove which Android installation sent a message (no attestation).
- SIM slot / subscription ID are not included in the payload.
- Multipart SMS is reassembled client-side; the body you receive is the full concatenated text.

## Suggested Remote regex (optional)

`SmsWorker` skips non-matching senders per Remote. Suggested starting filter (must be tested against real bank formats before production — over-restrictive filters miss real transactions):

```regex
(?is)^(?!.*(?:رمز|otp|کد[‌ ]?تایید|کد[‌ ]?تأیید)).*(?:واریز|برداشت|خرید|انتقال|مبلغ|مانده|تراکنش).*$
```

OTP classification MUST also happen server-side. The regex is an optimization, not a security boundary.
